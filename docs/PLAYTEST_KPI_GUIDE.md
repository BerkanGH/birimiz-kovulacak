# Playtest KPI guide and executable test plan

Generated by `python -I Tools/scripts/analyze_playtests.py --write-kpi-guide docs/PLAYTEST_KPI_GUIDE.md` from the same definitions the analyzer uses. Event names follow docs/ANALYTICS_ARCHITECTURE.md section 5. Unit of analysis: the anonymous friend group.

Common rules: missing data is `not_measured` or `insufficient_data`, never zero; strata (build_version + ruleset_version) are never pooled; synthetic data (fixtures, bot sims, matches with bots) is excluded unless `--include-synthetic` and then bannered `SYNTHETIC — not playtest evidence`; 10–20 friend groups are **exploratory evidence**: they can show where to look and which numbers are implausible, not that a mechanic works. Intervals resample whole groups; players of one group are not independent and repeated matches of one group are not new groups.

Metric statuses: `ok` (>= 2 groups, denominator > 0, coverage requirement met), `insufficient_data` (value shown if any, but too few groups/observations/coverage), `not_measured` (required event never present or no implementation).

## KPI definitions A-M

### KPI A - Access

- **Question:** Can friends get into a lobby, fill it, ready up and start without friction, and where do people leave?
- **Numerator:** join: lobby_joined; start failures: match_start_failed; departures: session_interrupted(mid_match) and match_abandoned by phase; times: lobby_fill_seconds, ready_seconds, wait_seconds
- **Denominator:** join: lobby_join_attempted; start failure: match_start_attempted; departures: match_started (matches)
- **Eligible population:** Consenting clients (join) and consenting host (start/match events); human, non-bot matches of one build+ruleset stratum
- **Observation window:** lobby open -> match_started (and the match for departures)
- **Consent / coverage requirement:** Client events need the client's own consent (self); host aggregate events need host consent only. Departure rows are skipped when a match has no client logs.
- **Authority source (events):** client: lobby_join_attempted, lobby_joined, lobby_join_failed, session_interrupted; host: match_start_attempted, match_started, match_start_failed, match_abandoned
- **Deduplication:** event_id (client random id, host deterministic hash); the analyzer keeps the first copy across host/client/re-imported files
- **Missing-data handling:** No client log -> metric not_measured/insufficient_data, never a 0% success rate. Retries count as new attempts; unknown reasons stay in their own bucket.
- **Interpretation limits:** Per attempt, not per person or group. Host-only logs cannot see failed joins that never reached the host. Lobby times depend on how the facilitator coordinated the group.

Implemented metrics: `A.join_success`, `A.join_failure_reason`, `A.join_wait_seconds`, `A.lobby_fill_seconds`, `A.ready_seconds`, `A.time_to_start_seconds`, `A.start_failure_rate`, `A.start_failure_reason`, `A.departure_per_match`

### KPI B - Completion and pacing

- **Question:** Do matches, days and rounds complete, how long do phases really last, and why do rounds end?
- **Numerator:** completed matches/rounds/days; phase exits with overrun_seconds > 0.5; RoundPlay exits ended by timer; early_submit rounds
- **Denominator:** terminal-observed matches (completed + abandoned); round_started; day_started; phase_exited
- **Eligible population:** Started matches with an observed host log; every phase exit of the stratum
- **Observation window:** match_started -> week_completed / match_abandoned; per phase entered -> exited
- **Consent / coverage requirement:** Host aggregate (H): host consent only, counts and durations, no per-player ids
- **Authority source (events):** host: phase_exited, round_started, round_finished, day_started, day_finished, week_completed, match_abandoned
- **Deduplication:** event_id; one phase_exited per phase per match (duplicate files collapse)
- **Missing-data handling:** Matches with neither week_completed nor match_abandoned are 'unknown end' (B.match_unknown_end) and excluded from the completion denominator; missing durations are skipped, not zeroed.
- **Interpretation limits:** Durations come from the host monotonic clock. A host crash loses private events and can look like an unknown end. Carried break seconds are only visible for early_submit rounds.

Implemented metrics: `B.phase_duration`, `B.overrun_rate`, `B.overrun_seconds`, `B.round_completion`, `B.day_completion`, `B.match_completion`, `B.match_unknown_end`, `B.abandon_phase`, `B.completion_reason`, `B.timer_ending_share`, `B.early_submit_share`, `B.saved_seconds`, `B.carried_seconds`, `F.post_submit_wait`

### KPI C - Phone participation per round

- **Question:** In each round, what share of observed players had at least one successful connected call?
- **Numerator:** distinct eligible OBSERVED players with >=1 successful connected call overlapping the round (phone_round_summary.participating, or derived from call intervals vs the RoundPlay window)
- **Denominator:** eligible observed players (phone_round_summary.observed, or players with a round_player_summary)
- **Eligible population:** Consenting, non-bot, connected players of a round
- **Observation window:** RoundPlay window of the round (phase_entered -> phase_exited)
- **Consent / coverage requirement:** all_participants: a call needs the consent of caller and callee; host aggregate summary needs host consent and carries observation_coverage
- **Authority source (events):** host: phone_round_summary (primary), phone_call_connected/finished (derivation), round_player_summary (fallback)
- **Deduplication:** a call is identified by (match_id, call_id) and counts once per participant; round summaries by (match, day, round)
- **Missing-data handling:** Failed, rejected and missed calls never count as participation. A round without observed players is skipped (not 0%). participation_rate='not_measured' rounds are skipped.
- **Interpretation limits:** Participation is a floor: unconsented players are outside the denominator. It measures a connected call, not conversation quality or speaking.

Implemented metrics: `C.phone_participation`, `C.observed_share`

### KPI D - Communication exposure

- **Question:** How quickly and how widely do players reach each other, and where does calling fail?
- **Numerator:** first-contact seconds (samples); calls and connected seconds; HHI of partner shares; busy/unanswered counts; players who attempted but never connected
- **Denominator:** player-rounds with contact (latency); call requests (failure rates); players who attempted (never-connect)
- **Eligible population:** Observed player-rounds and calls with both participants' consent
- **Observation window:** RoundPlay; call intervals are clipped to phases; connected time = interval union per player
- **Consent / coverage requirement:** all_participants for calls; self for round_player_summary
- **Authority source (events):** host: round_player_summary, phone_call_requested/connected/finished/failed/missed/rejected
- **Deduplication:** each call once globally (match_id, call_id), once per participant for per-player figures; overlapping calls of one player are unioned
- **Missing-data handling:** A player-round without contact has no latency (excluded and counted by D.no_contact_share) - never 0 s. Calls without a finished event are censored/unknown duration.
- **Interpretation limits:** Connected time is not speaking time. Short latency can mean a dominant caller. HHI is undefined with fewer than two connected calls.

Implemented metrics: `D.first_contact_latency`, `D.no_contact_share`, `D.call_duration`, `D.call_duration_participant`, `D.connected_seconds`, `D.connected_seconds_derived`, `D.unique_partners`, `D.partner_hhi`, `D.busy_failure_rate`, `D.call_failure_reason`, `D.unanswered_rate`, `D.attempt_never_connect`

### KPI E - Communication value

- **Question:** Do outcomes, contribution, decision revisions and career results differ between no-communication, voice-only, text-only and mixed rounds?
- **Numerator:** mean/rate of quality, income, cooperation credits, revisions, career total within each comm_mode
- **Denominator:** player-rounds (or cooperation opportunities / players) in that mode
- **Eligible population:** Observed player-rounds with a comm_mode and a resolved outcome; survived matches for career totals
- **Observation window:** one round; career totals per match
- **Consent / coverage requirement:** self (private_until_match_end events written at results; suppressed without consent)
- **Authority source (events):** host: round_player_summary(comm_mode), choice_outcome_resolved, choice_changed, career_breakdown
- **Deduplication:** (match, day, round, player slot) joins; duplicates removed by event_id
- **Missing-data handling:** Player-rounds lacking a comm_mode or an outcome are dropped from that mode, never counted as 'none'. Groups with <3 samples per mode are skipped for the dominance check.
- **Interpretation limits:** ASSOCIATIONS ONLY. Confounders: task type and role (some tasks need contact), partner availability, player skill, group, who chooses to talk, ordering effects. No causal claims.

Implemented metrics: `FB.q_contact_helped`, `E.mode_share`, `E.quality`, `E.income`, `E.cooperation_rate`, `E.revisions`, `E.career_total`, `E.silent_not_dominant`

### KPI F - Waiting and exclusion

- **Question:** Who waits or is left out: longest interaction gaps, post-submission waiting, busy partners, technical blocking?
- **Numerator:** gap/wait seconds (samples); player-rounds with wait >= 20 s; player-rounds blocked > 0
- **Denominator:** observed (submitted) player-rounds
- **Eligible population:** Observed players; worst-served = the single player with the largest mean gap per match
- **Observation window:** RoundPlay
- **Consent / coverage requirement:** self (round_player_summary)
- **Authority source (events):** host: round_player_summary(longest_gap_seconds, post_submit_wait_seconds, busy_failures, blocked_seconds)
- **Deduplication:** (match, day, round, slot)
- **Missing-data handling:** Players without a summary are UNKNOWN (F.observation_coverage shows the known share); unknown periods are never reported as zero waiting.
- **Interpretation limits:** Reading, thinking or listening is not boredom or exclusion. A long gap can be a deliberate choice. Pair with observer players_appeared_excluded.

Implemented metrics: `O.excluded`, `FB.q_reach_people`, `FB.q_too_much_waiting`, `F.longest_gap`, `F.post_submit_wait`, `F.post_submit_wait_over20`, `F.busy_failures`, `F.blocked_seconds`, `F.blocked_share`, `F.observation_coverage`, `F.worst_served_gap`

### KPI G - Decisions

- **Question:** How fast and how stable are decisions, before vs after contact, and what do they produce?
- **Numerator:** latency samples; choice_changed per submission; submissions after contact; timeouts; rejected actions; category counts; blame deltas
- **Denominator:** choice_submitted (per task); submissions + timeouts; observed player-rounds
- **Eligible population:** Observed submissions of a task
- **Observation window:** RoundPlay
- **Consent / coverage requirement:** self (M events at results); invalid actions are client events
- **Authority source (events):** host: choice_submitted, choice_changed, choice_timed_out, fault_points_changed; client: ui_action_rejected, message_rejected
- **Deduplication:** event_id; one submitted event per (player, field) final plus changes
- **Missing-data handling:** Missing latency is skipped. Timeouts are denominated by submissions + timeouts of the observed rounds. Categories are task specific (compare only within a task).
- **Interpretation limits:** Short latency can mean carelessness or a solved puzzle; revisions can mean learning. Do not rank tasks without difficulty control.

Implemented metrics: `O.confused`, `G.latency`, `G.revisions_per_submit`, `G.after_contact_share`, `G.timeout_share`, `G.invalid_actions`, `G.category_share`, `G.blame_delta`

### KPI H - Meetings and recordings

- **Question:** Do 7-second reveals play, how long do they run, where do they come from, who is exposed, and how do votes resolve?
- **Numerator:** reveals played; context-bearing reveals; repeat exposures; voters; abstentions; outcome counts; discussion seconds
- **Denominator:** recording_playback_finished; recording_playback_started; eligible voters; resolved meetings
- **Eligible population:** Meetings with recordings enabled (lobby toggle) of human matches
- **Observation window:** meeting dossier -> verdict; final: defense -> final verdict
- **Consent / coverage requirement:** recording playback: all_participants (both speakers); votes: voter; outcomes: host aggregate
- **Authority source (events):** host: recording_playback_started/finished, meeting_vote_submitted/resolved, final_vote_submitted/resolved, meeting_discussion_finished
- **Deduplication:** (match, pick_index) for reveals; last ballot per voter per meeting
- **Missing-data handling:** A vote target without consent is 'unconsented'. Speaking time per player is NOT measured (no event) -> not_measured. Matches without recordings enabled are not counted as 0 reveals.
- **Interpretation limits:** Playback success is technical, not intelligibility; pair with observer recording_was_intelligible / relevant / lacked_context. speech_ms is per-snippet metadata.

Implemented metrics: `O.meeting_too_short`, `O.meeting_too_long`, `M.recording_reaction`, `M.recording_referenced_later`, `M.recording_intelligible`, `M.recording_relevant`, `M.recording_contextless`, `FB.q_recording_awareness`, `FB.q_hear_over_music`, `H.playback_success`, `H.playback_failure`, `H.actual_duration`, `H.context_share`, `H.prior_exposure_share`, `H.same_group_share`, `H.speech_density`, `H.participant_coverage`, `H.repeat_exposed_players`, `H.vote_participation`, `H.abstain_share`, `H.no_action_vote_share`, `H.vote_outcome`, `H.discussion_duration`, `H.final_participation`, `H.final_abstain_share`, `H.final_fire_nobody_share`, `H.final_outcome`, `H.speaking_time_per_player`

### KPI I - Blame and fairness

- **Question:** How is blame distributed and recovered, and do warnings keep landing on the same people?
- **Numerator:** blame spread/top share per day end; changes by reason; remedial requests / accepted; meetings with a repeat warning; capped nominations; warnings on the previous blame leader
- **Denominator:** players (even split baseline); recovery opportunities; meetings where a repeat warning was possible; meetings where a player was at the warning cap
- **Eligible population:** Consenting players of human matches
- **Observation window:** day boundaries; per meeting
- **Consent / coverage requirement:** self (fault_points_changed, warning_assigned); host aggregate for recovery counts
- **Authority source (events):** host: fault_points_changed, warning_assigned, meeting_vote_resolved, recovery_opportunities, remedial_requested/resolved
- **Deduplication:** event_id; blame_after is the authoritative state
- **Missing-data handling:** Start blame is assumed 5 for players without events; the warning cap is 2. Missing outcome strings leave the cap metric empty.
- **Interpretation limits:** Concentration is not proof of unfairness (a saboteur may truly deserve blame). The cap prevents unlimited repeats, so compare repeat warnings only against eligible meetings.

Implemented metrics: `O.natural_accusation`, `O.accusation_evidence`, `O.accusation_reconsidered`, `FB.q_accusations_game_events`, `FB.q_recover_bad_start`, `I.blame_spread`, `I.blame_top_share`, `I.blame_top_share_baseline`, `I.change_reason`, `I.recovery_use`, `I.recovery_accept`, `I.recovery_output_added`, `I.repeat_warning`, `I.nomination_capped`, `I.target_was_blame_leader`, `I.warning_top_share`, `I.warning_top_share_baseline`

### KPI J - Economy and hybrid balance

- **Question:** Is income/evidence access concentrated, does sabotage get verified, and is productivity or wealth a near-automatic route to rank 1?
- **Numerator:** income/evidence Gini and top share; transfers; spend; verified/created incidents; sabotage loss; remedial recovery; objectives completed; career points; matches where a rank-1 player is also richest/best
- **Denominator:** players (even split baseline); created incidents; max output; objective events; matches with ranks
- **Eligible population:** Consenting players of surviving (for ranks) human matches
- **Observation window:** whole match (private events are flushed at results)
- **Consent / coverage requirement:** self (income, purchases, incidents), all_participants (transfers), host aggregate (company result)
- **Authority source (events):** host: income_credited, evidence_purchased, money_transferred, incident_created, sabotage_verified, task_output_resolved, remedial_resolved, objective_completed, career_breakdown, company_result
- **Deduplication:** event_id
- **Missing-data handling:** Private events exist only after the match ended and only for consenting players; matches that never flushed are skipped, not zero. Ranks are skipped when the company closed.
- **Interpretation limits:** Rank-1 coincidence must be compared with its chance baseline (J.*_baseline). Small groups make top shares high by construction (1/N).

Implemented metrics: `J.income_gini`, `J.income_top_share`, `J.income_top_share_baseline`, `J.evidence_gini`, `J.evidence_top_share`, `J.evidence_purchases`, `J.evidence_spend`, `J.transfers`, `J.transfer_amount`, `J.sabotage_verified_rate`, `J.sabotage_verify_delay`, `J.exposed_incident_share`, `J.sabotage_loss_share`, `J.remedial_recovery_share`, `J.objective_completion`, `J.career_component`, `J.rank1_is_richest`, `J.rank1_is_richest_baseline`, `J.rank1_is_best_quality`, `J.rank1_is_best_quality_baseline`, `J.company_closed_rate`, `J.final_productivity`

### KPI K - Technical

- **Question:** Which known failures recur, do reconnects work, how bad is phone/voice quality, and which exits are unexplained?
- **Numerator:** matches with a technical_failure of a category; reconnect successes; phone failures other than busy; voice loss/jitter/underruns; stuck_phase; sessions with no end event
- **Denominator:** matches with logs; reconnect outcomes; call requests; voice summaries; started sessions
- **Eligible population:** Any consenting client or host with logs
- **Observation window:** match or session
- **Consent / coverage requirement:** self (client), host aggregate
- **Authority source (events):** client+host: technical_failure, reconnect_*, voice_quality_summary, session_started/ended/interrupted; host: stuck_phase, unexpected_transition, phone_call_failed
- **Deduplication:** event_id
- **Missing-data handling:** Only caught failures are logged; a session with no end event is a 'possible crash' (unknown), not a confirmed crash; reconnect attempts without outcome stay unknown.
- **Interpretation limits:** Truncated or missing files look like crashes. Latency/loss are client-reported summaries.

Implemented metrics: `K.technical_failure_match`, `K.reconnect_success`, `K.reconnect_downtime`, `K.phone_failure_nonbusy`, `K.voice_loss`, `K.voice_jitter`, `K.voice_underruns`, `K.stuck_phase`, `K.unexpected_transition`, `K.possible_crash`

### KPI L - Voluntary rematch

- **Question:** Do groups choose to play again?
- **Numerator:** groups whose genuine opportunity was followed by a voluntary rematch_started (not auto, requests >= 1)
- **Denominator:** completed groups with an observed genuine opportunity (rematch_prompt_shown, or results reached with >=3 humans when no prompt events exist), excluding auto restarts and moderator-required repeats
- **Eligible population:** Groups of human matches of one stratum
- **Observation window:** from WeekResults until the next match_started of the group
- **Consent / coverage requirement:** self for client rematch events; host aggregate (H) for rematch_started and week_completed
- **Authority source (events):** client: rematch_requested, rematch_prompt_shown; host: rematch_started, week_completed
- **Deduplication:** event_id; rematch_started.previous_match_id links matches
- **Missing-data handling:** Intent (rematch_requested) and actual rematch are separate metrics; groups with no observed opportunity are excluded, not counted as 'no'.
- **Interpretation limits:** Facilitators can bias the choice. A group is one data point however many matches it plays; exploratory only.

Implemented metrics: `O.rematch_requested`, `FB.q_play_again`, `L.voluntary_rematch`, `L.rematch_intent`, `L.intent_to_rematch`

### KPI M - Shareable moments

- **Question:** Do matches produce moments that observers confirm as notable and players want to share? Six layers are kept apart.
- **Numerator:** (1) mechanical events per match; (2) player moment_marked; (3) groups with an observer-confirmed notable moment; (4) players wanting to share (feedback); (5) exports and (6) external shares
- **Denominator:** completed matches; groups with client logs; groups with adequate observation; answered feedback; (5)(6) none
- **Eligible population:** Observed human matches; adequate = observer rows covering >=50% of the group's logged matches
- **Observation window:** match
- **Consent / coverage requirement:** self for moment_marked and feedback; observer CSV needs no telemetry consent but no personal data
- **Authority source (events):** client: moment_marked; host: sabotage_verified, player_fired, company_failed; observer CSV; feedback CSV
- **Deduplication:** event_id; observer rows keyed by (group, match, day, round, moment_timestamp)
- **Missing-data handling:** (5) and (6) have no implementation in the game -> not_measured. Observer fields left blank are missing.
- **Interpretation limits:** A shareable moment is not predicted virality. Player-marked and mechanical events are candidates only; only observer confirmation counts as 'notable'.

Implemented metrics: `O.funny_betrayal`, `O.unexpected_accusation`, `O.surprising_outcome`, `FB.q_wanted_to_share`, `M.mechanical_events`, `M.player_marked_groups`, `M.player_marked_per_match`, `M.player_marked_category`, `M.groups_notable`, `M.notable_per_match`, `M.notable_category`, `M.notable_day`, `M.notable_phase`, `M.share_interest`, `M.observation_coverage`, `M.export`, `M.external_share`

## Test and observation plan H1-H9

All success criteria below are **design targets, not industry benchmarks**. They tell the team where to look, not that a mechanic works or fails.
Declared experiments available in the build: `rec_select` (legacy|context), `early_submit` (shorten|carry), `recording_awareness` (on|off).

### H1

- **Hypothesis:** Information exchange and negotiation improve outcomes; having no communication does not reliably dominate.
- **Metrics / events used:** E.quality/E.income/E.cooperation_rate/E.revisions by comm_mode, E.silent_not_dominant, D.no_contact_share, G.latency (after_contact); events: round_player_summary(comm_mode), choice_outcome_resolved, choice_changed, career_breakdown
- **Observation fields:** players_reconsidered_accusation, notes outside telemetry about whether contact was needed
- **Provisional success criteria:** Design targets, not industry benchmarks: in <= 1/3 of groups the no-communication mean quality exceeds the communicating mean; communicating rounds are at least as good in most information tasks.
- **Minimum data:** >= 10 groups, >= 3 player-rounds per mode and group; report per task
- **Confounders:** task needs contact by design, role, skill, partner availability, self-selection of talkers
- **Declared experiment:** none declared (observational)

### H2

- **Hypothesis:** At 3-6 players everyone has useful opportunities to act and communicate without excessive exclusion or waiting.
- **Metrics / events used:** C.phone_participation, F.longest_gap, F.post_submit_wait(_over20), F.blocked_share, D.busy_failure_rate, B.early_submit_share, F.worst_served_gap by player_count; events: phone_round_summary, round_player_summary, phone_call_failed, round_finished
- **Observation fields:** players_appeared_excluded, meeting_felt_too_short/long
- **Provisional success criteria:** Design targets, not industry benchmarks: phone participation >= 80% of observed players per round; <= 20% of submitted player-rounds waiting >= 20 s; worst-served mean gap not more than 2x the group median.
- **Minimum data:** >= 3 groups per player count (3/4/5/6) before comparing counts
- **Confounders:** task mix, group familiarity, call-handling habits, early-submit policy
- **Declared experiment:** early_submit (shorten|carry): compare waiting and carried break seconds

### H3

- **Hypothesis:** Seven-second reveals are understandable and relevant often enough.
- **Metrics / events used:** H.playback_success, H.context_share, H.speech_density, H.participant_coverage, H.repeat_exposed_players, M.recording_intelligible/relevant/contextless/reaction/referenced_later; events: recording_playback_started/finished
- **Observation fields:** recording_was_intelligible, recording_was_relevant, recording_lacked_context, recording_created_reaction, recording_was_referenced_later
- **Provisional success criteria:** Design targets, not industry benchmarks: >= 90% playback success; >= 60% of observed reveals coded relevant and >= 70% intelligible; contextless reveals < 30%.
- **Minimum data:** >= 30 observed reveals over >= 8 groups
- **Confounders:** speaker volume, music ducking, room noise, observer coding drift
- **Declared experiment:** rec_select (legacy|context): compare relevance/context share

### H4

- **Hypothesis:** Recording awareness does not eliminate candid negotiation.
- **Metrics / events used:** C.phone_participation, D.call_duration, D.no_contact_share, E.mode_share, FB.q_recording_awareness by exp.recording_awareness; events: phone_*, round_player_summary, lobby_created/match_started(recordings_enabled)
- **Observation fields:** natural_accusation_occurred, players_appeared_confused
- **Provisional success criteria:** Design targets, not industry benchmarks: recordings-on phone participation and call duration at least 70% of the recordings-off level; most players answer 'No' or 'Somewhat' to the awareness question.
- **Minimum data:** >= 5 groups per arm; assign the arm per group, never per player
- **Confounders:** novelty of the first match, group size, order of arms
- **Declared experiment:** recording_awareness (on|off) via the lobby recordings toggle - declared experiment

### H5

- **Hypothesis:** Accusations refer to observable events and evidence rather than consistently the same disliked player.
- **Metrics / events used:** O.accusation_evidence, O.accusation_reconsidered, I.target_was_blame_leader, I.warning_top_share vs baseline, I.repeat_warning, I.nomination_capped, H.vote_outcome; events: meeting_vote_resolved, warning_assigned, evidence_presented, fault_points_changed
- **Observation fields:** natural_accusation_occurred, accusation_referenced_game_evidence, players_reconsidered_accusation, unexpected_accusation
- **Provisional success criteria:** Design targets, not industry benchmarks: >= 60% of observed accusations reference game evidence; the same player is not the warning target in more than half of meetings in most groups.
- **Minimum data:** >= 10 groups with observers; >= 3 meetings per match
- **Confounders:** friendship dynamics, evidence availability, observer subjectivity
- **Declared experiment:** none declared

### H6

- **Hypothesis:** A bad early blame outcome has a credible recovery path.
- **Metrics / events used:** I.recovery_use, I.recovery_accept, I.recovery_output_added, I.blame_spread/top_share by day, J.remedial_recovery_share, FB.q_recover_bad_start; events: recovery_opportunities, remedial_requested/resolved, fault_points_changed
- **Observation fields:** players_appeared_confused (about recovery)
- **Provisional success criteria:** Design targets, not industry benchmarks: >= 30% of players with options request remedial work; >= 50% of requests accepted; blame leader share does not stay above 2x the even split through the last day.
- **Minimum data:** >= 10 groups; matches with at least one early warning
- **Confounders:** partner willingness, task output already at max, cap rules
- **Declared experiment:** none declared

### H7

- **Hypothesis:** Productivity creates cooperation pressure without making the hardest worker or richest player the automatic winner.
- **Metrics / events used:** J.rank1_is_richest vs baseline, J.rank1_is_best_quality vs baseline, J.career_component, J.company_closed_rate, J.final_productivity, J.income_top_share vs baseline; events: career_breakdown, company_result, income_credited
- **Observation fields:** surprising_outcome
- **Provisional success criteria:** Design targets, not industry benchmarks: rank-1 coincides with the richest (or best-quality) player no more than ~2x the chance baseline; company closes in roughly 10-40% of matches (neither always nor never).
- **Minimum data:** >= 20 surviving matches over >= 10 groups
- **Confounders:** ties, objective luck, sabotage exposure, group skill
- **Declared experiment:** none declared (CareerTargetPercent is a possible future experiment)

### H8

- **Hypothesis:** Matches produce observer-confirmed funny betrayals, unexpected accusations or surprising outcomes, and some players want to share them.
- **Metrics / events used:** M.groups_notable, M.notable_per_match, M.notable_category/day/phase, M.player_marked_*, M.share_interest, M.mechanical_events, M.observation_coverage; M.export and M.external_share are not_measured; events: moment_marked, sabotage_verified, player_fired, company_failed
- **Observation fields:** funny_betrayal, unexpected_accusation, surprising_outcome, notable_funny_moment
- **Provisional success criteria:** Design targets, not industry benchmarks: >= 60% of adequately observed groups have >= 1 confirmed notable moment; >= 0.5 confirmed moments per observed match; a clear minority of players answer Yes to wanting to share.
- **Minimum data:** >= 10 adequately observed groups
- **Confounders:** observer eagerness, group extroversion, drink/venue
- **Declared experiment:** none declared

### H9

- **Hypothesis:** Music supports tension and comedy without impairing conversation, recording intelligibility or concentration.
- **Metrics / events used:** FB.q_hear_over_music, M.recording_intelligible, K.voice_loss/underruns, D.call_duration, G.latency; events: music_cue_changed, voice_quality_summary, recording_playback_*
- **Observation fields:** recording_was_intelligible, players_appeared_confused
- **Provisional success criteria:** Design targets, not industry benchmarks: >= 80% of players answer Yes/Somewhat to hearing calls and reveals over music; intelligibility coding does not drop in ducked-off cues.
- **Minimum data:** >= 10 groups with feedback; >= 20 observed reveals
- **Confounders:** speakers/headphones, volume settings, room noise
- **Declared experiment:** none declared (a music on/off arm would need to be added)
