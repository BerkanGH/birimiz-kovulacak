# Analytics architecture (Gameplay Analytics & Playtest Intelligence)

Status: **contract** (lead-owned sections 1–6) + implementation notes (telemetry track, section 7+). Event names and
parameters below are binding for the telemetry implementation (`Game/Assets/Game/Core/Telemetry`), the machine-readable
catalog (`docs/analytics/event_catalog.json`, generated from code) and the offline analyzer
(`Tools/scripts/analyze_playtests.py`). Change requests go through the lead.

Analytics **observes**; it never changes rules, timers, outcomes, recording behaviour or authority. Telemetry failures
never affect gameplay, networking or voice.

## 2. Envelope (one JSON object per line)

```json
{"schema_version":1,"event":"phase_exited","event_version":1,"event_id":"h-3f9a…","authority":"host",
 "timestamp_utc":"2026-11-01T20:15:03.120Z","monotonic_elapsed_seconds":412.53,"environment":"playtest",
 "session_id":"s-…","match_id":"m-…","week_id":1,"anonymous_group_id":"g-…","anonymous_player_id":"p-…",
 "player_slot":2,"player_count":4,"is_bot":false,"day_index":0,"round_index":1,"task_number":1,"phase":"RoundPlay",
 "task_id":"invoice_reconcile","task_version":1,"game_version":"0.4.0","build_version":"202611012015-a1b2c3",
 "ruleset_version":"v4.0-hybrid","test_cohort":"friends_wave1","experiments":{"rec_select":"context","early_submit":"carry"},
 "observation_coverage":0.75,"params":{"duration_seconds":74.8,"planned_duration_seconds":75.0,"completion_reason":"timer"}}
```

- Fields not applicable to an event are **omitted** (never written as 0). `anonymous_player_id`/`player_slot`/`is_bot`
  describe the event's *subject* player when there is one.
- `monotonic_elapsed_seconds`: host events = host engine time (monotonic, `HostLineController.Now`); client events =
  `Stopwatch` since process start. Durations come from monotonic clocks only.
- `observation_coverage`: on aggregate events, consenting non-bot humans / human players in the match.
- Experiments: `experiments` lists every declared assignment active for the match; an event about one experiment
  also carries `experiment_id` + `experiment_variant`.

## 3. Identity, scope, lifetime

| Id | Generated by | Scope / lifetime |
|---|---|---|
| `anonymous_player_id` (`p-` + 128-bit random hex) | each install, only after consent ≥ local | until withdrawal or "reset id"; never derived from name, account, device, IP |
| `session_id` (`s-…`) | host, per hosting session (lobby lifetime) | shared to clients in `LineLobbyView.SessionId` |
| `match_id` (`m-…`) | host, per match | `LineSetup.MatchId` → every view and result |
| `anonymous_group_id` (`g-…` or facilitator code `G07`) | host: `-playtestgroup` launch arg / lobby field, else random per session | lets repeated matches of one friend group be grouped; groups — not players — are the unit of analysis |
| `event_id` | host events: `h-` + 64-bit FNV-1a of `match_id|event|logical_key` (deterministic, survives retries and re-imports); client events: `c-` + random 128-bit, fixed when the event object is created | analyzer dedupes on it |

Bots: `is_bot = true`; matches with any bot carry `has_bots`; fixture/bot/human data are separated by
`environment`/`test_cohort` (`synthetic_fixture`, `bot_sim`, humans = facilitator cohort).

## 4. Authority, sensitivity, consent

- **Authority**: every gameplay fact is logged once, by the host (`authority:"host"`). Clients log only client-local
  facts (UI, onboarding, settings, connection experience, moment markers, music cues) with `authority:"client"`.
  The same logical event is never emitted by both, so host and client logs merge without double counting.
- **Sensitivity**:
  - `public` — written immediately.
  - `private_until_match_end` — contains information other participants must not learn during the match (choices,
    objectives, incidents, money, choice categories). The host holds these **in memory** (bounded) and writes them only
    at `WeekResults`/abandon; a host crash loses them (reported as coverage loss). The host player can therefore not
    read colleagues' secrets from their own log folder mid-match.
  - `local_only` — never sent to the cloud sink.
- **Consent** (per participant, sent to the host in `LineConnectionPayload.TelemetryConsent` and updated by
  `NetSession` RPC): 0 unknown → nothing collected; 1 denied; 2 local logs; 3 local + cloud. Rules per event:
  - `self` — the subject player's consent (client events; per-player host events).
  - `all_participants` — every player referenced (calls: caller and callee; transfers: both; remedial: both).
  - `voter` — the voter's consent; a vote target without consent is written as `"target":"unconsented"`.
  - `host_aggregate` — host consent; counts only, no per-player ids (match summaries, meeting outcomes).
  Missing consent ⇒ the event is **suppressed**, never converted to zero; aggregates carry `observation_coverage`.
  The host's consent never authorizes other participants' events. Gameplay **recording** consent (lobby toggle) is
  separate from analytics consent.
- **Withdrawal**: collection stops immediately; queued unsent events of that player are purged; local files can be
  deleted from Settings → Privacy; the anonymous id is reset. Events already written by *another machine* (the host's
  log) cannot be deleted remotely: the facilitator runs `analyze_playtests.py --purge-player <id>` on collected files.
  Cloud deletion uses the SDK's deletion request when available (only for the requesting player's own SDK identity).
- **Never collected**: audio, recordings or audio paths, transcripts, any player-authored text (messages, emails,
  complaints, names, quotes), usernames, Steam ids, IPs, emails, phone numbers, reconnect tokens, raw exception
  messages (only exception type names and categories).

## 5. Event list (binding names; params typed)

Types: `i` int, `f` float seconds, `b` bool, `e` enum string, `id` short id string. `slot`-typed params are player slots;
the analyzer resolves them to anonymous ids through `player_slot_map` (§5.9). Sensitivity: P public, M
private_until_match_end. Consent: S self, A all_participants, V voter, H host_aggregate.

### 5.9 Correlation
- `player_slot_map` (host, P per consenting player, at match start): `slot` slot, `anonymous_player_id` id, `is_bot` b.
- Client events carry the client's own `anonymous_player_id` and `player_slot` (from the welcome).

## 6. Routing

- **Local JSONL**: every collected event (subject to consent ≥ 2) → `<persistentDataPath>/telemetry/<environment>/
  events_<session_id>_<n>.jsonl`, rotated at 1 MB, at most 20 files / 30 days per environment; partial last lines are
  tolerated by the analyzer.
- **Cloud (Unity Analytics)**: only events marked `cloud`, only for consent 3, only the **local** player's own client
  events plus host-aggregate (H) events without slot params: `session_started`, `session_ended`, `lobby_join_failed`,
  `match_started`, `week_completed`, `phase_exited` (phase + completion_reason + duration bucket), `round_finished`
  (task_id + output bucket), `meeting_vote_resolved` (outcome), `final_vote_resolved` (outcome), `company_result`
  (closed + permille bucket), `rematch_started`, `tutorial_closed`, `technical_failure`. Detailed correlation fields
  (slots, match/event ids) stay local.
- **Debug sink**: in-memory ring for the development overlay; respects the same visibility rules (host-only
  diagnostics shown only on the host; private-until-match-end events never displayed during a match).
