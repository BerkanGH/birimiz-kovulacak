# Analytics setup and operation

Contract: `docs/ANALYTICS_ARCHITECTURE.md`. Event reference (generated): `docs/ANALYTICS_EVENT_CATALOG.md`, `docs/analytics/event_catalog.json`.
Analytics observes; it never changes rules, timers, outcomes, voice or networking, and a failure in it never reaches gameplay.

## 1. Enable / disable

| How | Effect |
|---|---|
| `StreamingAssets/Config/telemetry_config.json` (`Enabled`, `Local`, `Cloud`, `Environment`, ...) | Defaults: enabled, local on, cloud **off**, environment `"auto"` = `development` in the editor and development builds, `playtest` otherwise. `ProjectBuilder` does not overwrite this file. |
| `-telemetry off` | Service disabled: no events, no files, no sinks, near-zero overhead (one volatile read per call). |
| `-telemetry local` | Local JSONL only (cloud route forced off). |
| `-telemetry cloud` | Also enables the cloud route (still needs the optional package, see section 6, and consent level 3 per player). |
| `-cohort friends_wave1`, `-playtestgroup G07`, `-experiment rec_select=context` (repeatable), `-telemetryenv playtest` | Envelope labels (`test_cohort`, `anonymous_group_id`, `experiments`). Invalid labels are dropped, never written. |

Nothing is collected until the player chooses a consent level (section 2). `session_started` is emitted when consent first becomes >= 2.

## 2. Consent flow

Levels: 0 unknown (nothing collected), 1 denied, 2 local logs, 3 local + cloud. `TelemetryConsentStore` (PlayerPrefs `telemetry.consent`) implements `ITelemetryPrivacy`:

- First launch: the UI shows the prompt while `NeedsConsentPrompt` and calls `SetConsent(1|2|3)`. (UI owner: not part of this track.)
- The anonymous id (`p-` + 128 random bits) is created **only** after consent >= 2, stored in PlayerPrefs `telemetry.anon_id`, deleted on withdrawal, regenerated by `ResetAnonymousId()`.
- The client sends `TelemetryConsent` and `AnonymousPlayerId` in `LineConnectionPayload` and again through an update RPC whenever `TelemetryConsentStore.ConsentChanged` fires (lead wiring, see handoff). The host registers each seat with `HostTelemetryBridge.PlayerConsent`.
- Host events about a player require **that player's** consent; calls/transfers need every participant. The host's consent never authorizes other people's events. Missing consent suppresses an event (it is not written as zero); aggregates carry `observation_coverage`.
- Withdrawal (`SetConsent(<2)`): collection stops immediately, queued events and the private buffer of that participant are purged, the id is deleted. Purged counts appear as `telemetry_queue_dropped` (`consent_withdrawn`) while consent still allows reporting, otherwise only in the in-memory counters.
- Gameplay *recording* consent (lobby toggle) is separate from analytics consent.

## 3. Where the logs are

`<persistentDataPath>/telemetry/<environment>/events_<session_id>_<n>.jsonl`; on Windows
`%USERPROFILE%\AppData\LocalLow\Leonidas Studio\Birimiz Kovulacak\telemetry\<environment>\`.
One JSON object per line; files rotate at 1 MB; at most 20 files and 30 days per environment (oldest pruned first). A torn last line after a crash is possible and tolerated by the analyzer.

The **host** machine holds the gameplay facts of the whole group (with each player's consent); clients hold only their own client-local events. Collect the host's folder after a session.

## 4. Export workflow (playtests)

1. Player/host: Settings -> Privacy -> "Export logs" (`ITelemetryPrivacy.ExportLogs()`) writes `telemetry/export_<utc timestamp>.zip` next to the environment folder, or "Open folder" (`OpenLogFolder()`) to copy the files by hand.
2. Facilitator: collect the host's zip first, then clients'. Unzip into one folder per group.
3. Run the analyzer track's tools on the folder. The analyzer dedupes by `event_id` (host ids are deterministic, so re-imports do not double count) and resolves `slot` parameters through `player_slot_map`.

## 5. Playtest group code, cohorts, experiments

- Group: `-playtestgroup G07` (or `GroupId` in the config). Without it the host generates a random `g-...` per hosting session. Groups, not players, are the unit of analysis.
- Cohort: `-cohort friends_wave1` -> envelope `test_cohort`. Use `synthetic_fixture` / `bot_sim` for non-human data.
- Experiments: `-experiment early_submit=carry`, or `Experiments: ["rec_select=context"]` in the config, plus the lobby's `Experiments` list (host). All declared assignments are written on every event of the match (`experiments` map).
- Label rules: lowercase letters, digits, underscore, at most 24 characters.

## 6. Unity Analytics (cloud) - NOT installed, NOT verified

Cloud configuration is not available in this repository. The package is **not** in `Packages/manifest.json`.
`Game/Assets/Game/Scripts/Telemetry/UGS/` is its own assembly (`BirimizKovulacak.Telemetry.UGS.asmdef`, `versionDefines` -> `BK_UGS_ANALYTICS`, `defineConstraints: ["BK_UGS_ANALYTICS"]`); while `com.unity.services.analytics` is absent it is excluded and the game builds without it. ## 7. Deletion and its limits

- Settings -> Privacy -> delete (`DeleteLocalData()`): flushes, then deletes this machine's `events_*.jsonl` and asks the cloud sink (when present) for `RequestDataDeletion()` for this install's SDK identity.
- Limits: events a *host* wrote about other players live on the host's machine and cannot be deleted remotely. The facilitator purges them from collected files with the analyzer's `--purge-player <anonymous_player_id>` (analyzer track). Already exported zips and copied folders are outside the game's control. Cloud deletion covers only the requesting player's SDK identity and is processed by Unity's service.
- A player who withdraws mid-match keeps already-written lines in the host's log of the current match (purge by id afterwards); pending lines are dropped.

## 8. Privacy and legal items that need human review (no compliance claim is made)

- Wording and presentation of the consent prompt (language, granularity, "local" vs "cloud" explanation, withdrawal path); whether the pseudonymous id and group id count as personal data in the intended jurisdictions (KVKK / GDPR assessment, data controller, retention period, cross-border transfer for Unity Analytics).
- Minors and playtest recruitment consent forms; the facilitator's handling and storage of collected zips.
- Whether the host's log of colleagues' *consented* data (calls, choices after match end) is acceptable to the participants as explained in the prompt.
- Retention (30 days local default) and the deletion workflow for host-held data.
- Unity Analytics terms, data residency and the dashboard's own retention/deletion behaviour.

Technical measures in place: no audio, recordings, transcripts, player-authored text, names, IPs, Steam ids, reconnect tokens or exception messages are ever written (only exception type names); strings in events come only from catalog enum sets or validated id patterns; private-until-match-end events stay in host memory until results/abandon; ballots are written when they become public.

## 9. Overlay

F9 in the editor and development builds shows consent/enablement, abbreviated ids, phase, counters, per-name volume, queue/drops/sink errors, recent events, your own call/submit progress and (host only) observation coverage. Private-class events (names and counts) are hidden during a match and host-only diagnostics appear only on the host.
